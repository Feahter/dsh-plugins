# 插件取代与废弃流程

DSH 插件市场的索引格式（format 1）**没有** `deprecated` / `replacedBy` / `hidden` 字段——往条目里加这类键会被静默忽略（官方 `docs/user/guide/plugin-market.md`：未识别字段在每一层都被忽略）。所以「某个插件被新包取代」必须用格式已经支持的手段表达。

## 四步

1. **新包承担能力**。新包用自己的包名发布，不接管旧包名（旧包的已装用户会一直停在旧版本）。
2. **旧条目的描述首句写清取代关系**：`Superseded by <新包名> <版本>：<一句话为什么>。` 中英双语都要写，市场卡片直接显示这段文字。
3. **旧条目不再发新版**：`versions` 只保留历史（历史版本改不动，也不该改）；如果旧包已经明确不可用，就把它的 `versions` 收窄到还兼容当前宿主的那些版本，或者整条移除。
4. **旧包 README 首屏加横幅**，并给出迁移对照表（旧包的哪块能力去了新包的哪个文件/模式）。

> 官方市场里 134 条真实条目中，`deprecated`/`replacedBy`/`hidden` 字段出现 0 次；被宿主内置取代的能力会显示成「Provided by DSH」，那是宿主侧状态，不是索引字段。所以不要发明字段。

## 本仓库当前状态

| 旧插件 | 状态 | 接替者 | 说明 |
| --- | --- | --- | --- |
| `dsh-realtime-voice` | 已被取代（0.3.0 为最后一版，0.3.1 起只做取代声明） | `dsh-voice-companion` ≥0.4.0（`src/client/dictation.js` + `polish.js`） | 输入框听写、两句连读校正、口述翻译 |
| `dsh-voice-control` | 已被取代（0.1.0 为最后一版，0.1.1 起只做取代声明） | `dsh-voice-companion` ≥0.4.0（`src/client/hotkey.js`） | 热键按住说话、按会话路由投递 |

两个包仍然保留在索引里，因为已经有用户装过；但描述首句会写明取代关系，README 首屏会有横幅，并且不再接新功能。

## 什么时候才真的移除

- 旧包在**当前宿主**上已经无法启动（例如它依赖的宿主服务被删掉），并且新包已经覆盖它的全部能力；
- 或者旧包的安装会给用户数据带来风险（写入格式与新版不兼容）。

移除时按第 3 步：从 `index.json` 删掉该条目，同时从两个 README 的目录表与 `llms.txt` 里删掉，跑 `node docs/verify-readme.mjs` 与 `node scripts/check-manifest.mjs` 确认没有残留引用。
