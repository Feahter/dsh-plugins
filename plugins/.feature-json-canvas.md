## 新增工具与参数

### `mind_canvas_export_json_canvas`

入参：

- `doc?: string` —— 脑图标题（部分匹配），省略用当前脑图。
- `pretty?: boolean` —— 是否缩进，默认 `true`。

返回：

```json
{ "doc": "…", "docId": "…", "format": "json-canvas", "specVersion": "1.0",
  "nodes": 8, "edges": 7, "bytes": 2630, "json": "{\"nodes\":[…],\"edges\":[…]}" }
```

节点：`id`/`type:"text"`/`text`/`x`/`y`/`width`/`height` 都是规范字段，坐标与宽高为整数；`x/y` 取已有坐标（四舍五入），缺失时按树层级生成稳定位置；`width` 固定 208，`height` 按文本行数估算（与界面共用 `estimateHeight`）。`color` 是六种色调对应的 `#RRGGBB`。边：`fromNode` 为父、`toNode` 为子，`id` 按前序稳定生成。同一份 doc 重复导出字节级一致。

### `mind_canvas_import_json_canvas`

入参：

- `json: string` —— 整份 JSON Canvas 1.0 文本（运行时也接受已解析对象）。
- `doc?: string` —— 要合并进的脑图标题；省略或匹配不到则新建一张。

返回：

```json
{ "doc": "…", "docId": "…", "created": true, "written": true,
  "imported": 2, "skipped": 9, "skippedNodes": 4, "skippedEdges": 5,
  "warnings": ["…"] }
```

合并到已有脑图时，若导入节点 id 与现有节点冲突，会加 `_2`/`_3` 后缀并同步重映射 `parentId`/边；导入节点标记 `source: { kind: "json-canvas" }`。

### 面板入口

导出按钮菜单新增第 5 个格式 **JSON Canvas（Obsidian / Heptabase）**，下载 `.canvas` 文件（`renderExport(doc, "jsoncanvas")`）。导入按任务允许的范围只做 Host 工具，没有加面板导入按钮。

## 导入跳过策略

节点：

- 不是对象 → 跳过。
- `type` 不是 `text`（`file` / `link` / `group` / 未知 type）→ 跳过并 warning；其余节点继续导入。
- `id` 缺失或重复 → 跳过。
- `text` 缺失按空字符串存；`x`/`y` 四舍五入取整，缺失或非数字按 0；`width`/`height` 忽略（模型无尺寸字段）。
- `color`：精确 hex / 最近的六色调 / 预设 `"1".."6"` 映射到 `tone a..f`；无法识别时用默认色并 warning。

边：

- 不是对象、缺 `fromNode`/`toNode` → 跳过。
- 端点不在“已成功导入的 text 节点”里（含指向 file/link/group/未知节点的边）→ 按孤边跳过。
- 自引用 → 跳过。
- 目标节点已有父节点（第二条父边）→ 跳过。
- 从 `fromNode` 沿父链能走回 `toNode`（会成环）→ 跳过。
- `fromSide`/`toSide`/`label`/`color` 等模型没有的边元数据忽略，不额外计数。

计数：

- `skipped = skippedNodes + skippedEdges`。
- warning 默认最多 40 条，超出追加一条“另有 N 条未列出”。
- 只有整串不是合法 JSON、顶层不是对象时抛错；单条脏数据只 warning，不会让整份失败。
