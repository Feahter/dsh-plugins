## 1. 产品形态

### 1.1 一句话定位

v0.4 的看板是**页面内的常驻悬浮核心**：一颗会呼吸、会随声音变形的科幻核（3D），下面挂字幕与麦克风控制，收起后是一枚 44px 的状态胶囊。所有外观由主题 token 决定，主题可以用一句话让模型改、也可以手改到每个像素。

### 1.3 尺寸 / 位置 / 透明 / 穿透

- 默认尺寸：展开 340×316（token `board.width` / `board.height`，可改）；收起 44×44（CSS 固定，不进 token，避免拖拽热区被改坏）。
- 默认位置：右下 18px（CSS `right/bottom`，`avatar.js:52`），一旦拖过就写 `dsh.voice-companion.pos`（`avatar.js:588`、`:839-846`），刷新恢复。
- 贴边吸附：拖拽结束时若距左/右/上/下边 < 24px，吸附到 12px；复用现有 `place()` 的边界收敛（`avatar.js:781-806`），**不新增存储键**。
- 透明：卡片背景用两条 token 起止色（默认 α 0.88/0.94）+ `backdrop-filter`；「裸核模式」把 `board.bgFrom/bgTo` 设为 `transparent` 且边框透明，只剩核心与字幕。
- 点击穿透：**只做层内穿透**——canvas 与光晕层 `pointer-events:none`；可选开关「轻穿透」把 stage/bubble 也设为穿透，控制条保持可点。**OS 级穿透（窗口不接收鼠标）不可能**：客户端只是页面里的一个 `div`，挂载在 `document.body`（`src/client/index.js:325`），没有 BrowserWindow 句柄。本设计不承诺做不到的事。

### 1.4 借鉴 / 不借鉴社区桌宠

公开可检索的 dsh-pet 系插件（[TuWeiZhi/dsh-pet](https://github.com/TuWeiZhi/dsh-pet) 的 README 自述：「碎碎念全本地语句池 / 气泡可收起 / 自动行为间隔 / 不出屏幕」；另有 [@asahimoon/dsh-desktop-pet](https://www.npmjs.com/package/@asahimoon/dsh-desktop-pet)、[@tuweizhi/dsh-pet](https://www.npmjs.com/package/@tuweizhi/dsh-pet)）。本机未安装这些插件，除 README 自述外未逐一核对实现 `[推]`。

| 借鉴 | 不借鉴 | 理由 |
| --- | --- | --- |
| 无边框悬浮、从页面角落浮起 | 独立置顶窗口 / 系统托盘 / 开机自启 | DOM 插件没有窗口权限；DSH Web 里能做的上限就是 `position:fixed` + 极高 z-index（现为 2147483000） |
| 拖拽任意位置并记忆 | 随机游走 / 自动走动 | 语音面板正在录音时移动会打断瞄准与点击；「自动行为间隔」只保留在核心的呼吸相位上 |
| 收起成小挂件（点一下展开） | 桌面级点击穿透 | 见 1.3；会直接毁掉拖拽与按钮 |
| 不出屏幕（边界收敛 + 视口 resize 重收敛） | 本地随机语句池「碎碎念」 | 与语音字幕/TTS 抢话语权；空闲文案交给模型人格，不引入第二套文案源 |
| 气泡可收起、状态点常驻 | 右键菜单当唯一入口 | 面板已有齿轮与键盘可达按钮（focus-visible 已有样式），右键菜单在网页里不可发现 |

## 2. 3D 形象技术方案

### 2.1 裁决：自研极简 WebGL（SDF 光线步进），2D canvas / CSS 为降级

| 候选 | 增量体积 | 与构建约束 | 60fps | 结论 |
| --- | --- | --- | --- | --- |
| vendor three 子集 | three 即使 tree-shake 后也 ≥ 300KB；单文件内联版 ≥ 600KB | **直接违反**：`build-client.mjs:23-30` 删 `import` 后拼接，无法解析 three 的模块图；也没有 bundler 做 tree-shake | 好 | **否决**（体积 ×3.5，且工程上做不出来） |
| CSS 3D（多层 div + conic/radial-gradient + transform） | ~3KB | 通过 | 合成层多时掉帧 `[推]` | 作为**第 4 级降级**，不是主路径：没有逐像素辉光/菲涅尔，做不出全息核的「体积感」 |
| 2D canvas 伪 3D（投影线框 + `lighter` 叠加） | ~8KB | 通过 | 中（每帧 path + 径向渐变，`shadowBlur` 很贵） | 作为**第 3 级降级**，同时充当 WebGL 的「low」画质档 |
| **自研 WebGL SDF**（一个全屏 quad + fragment shader） | ~17KB | 通过（纯 JS + 字符串，无 import） | 高（无几何/矩阵代码，像素量可控） | **选它** |

选它的四条硬理由：

1. **零 import**：只需要 `canvas.getContext('webgl2'|'webgl')`，着色器是模板字符串，`flatten()` 完全无感（`build-client.mjs:23-30`）。
2. **体积**：没有顶点数据、没有模型、没有矩阵库；视觉复杂度全在 ~90 行 GLSL 里。
3. **降级天然**：拿不到上下文就换 2D canvas，再拿不到就换纯 CSS（同一份状态→参数表驱动三种后端）。
4. **状态联动**：`uLevel/uPhase/uPulse` 三个 uniform 就能把「说话时核心膨胀、倾听时环收缩、思考时环加速、报错时去饱和抖动」全部表达，不需要骨骼/动画系统。

**WebGL2 与 WebGL1 共用一份 GLSL ES 1.00 源码**（`attribute/varying/gl_FragColor`，WebGL2 兼容 ES 1.00 着色器）。所以代码里只有一条着色器路径，降级只是换 `getContext` 的参数。

### 2.3 着色器思路（关键片段，不是完整实现）

场景是一个 `sdScene(p)`：

```glsl
// 伪代码：所有距离场在做完旋转变换后叠加
float sdScene(vec3 p) {
  float core = length(p) - (0.52 + 0.05*sin(uTime*1.7) + 0.14*uLevel);   // 能量核：半径随电平膨胀
  float ring1 = sdTorus(rotY(p,  uTime*0.45), 0.80, 0.012);              // 轨道环 A
  float ring2 = sdTorus(rotX(p, -uTime*0.30), 0.66, 0.010);              // 轨道环 B
  return min(core, min(ring1, ring2));
}
```

- 步进 40 步（LITE 变体 24 步），命中后 4 个采样点求法线；`fresnel = pow(1.0 - dot(n, -rd), 3.0)` 做边缘光。
- 辉光不靠后处理：步进过程中累计 `glow += 0.02 / (0.03 + minDist)`，命中后 `col += uGlowColor * glow * 0.9`。
- 扫描线：`sin(vUv.y * 220.0 + uTime * 6.0) * 0.02`；抖动：`uJitter * sin(uTime*91.0) * 0.004` 加到 uv（报错态）。
- 色板三色 uniform：`uInner`（核）、`uRim`（菲涅尔）、`uGlow`（辉光），全部来自主题 `core.palette.<state>`。
- 时间缩放 `uSpeed = 1/motion.speed`；`prefers-reduced-motion` 时 `uTime` 冻结、只保留 `uLevel` 驱动的透明度。

顶点侧只有一个 fullscreen quad：`attribute vec2 aPos; varying vec2 vUv;`，`vUv = aPos*0.5+0.5`，无矩阵。

### 2.4 后端与降级链（可执行）

```
启动 → canvas.getContext('webgl2') 成功 → kind='webgl2'
     → 失败 → getContext('webgl') 成功 → kind='webgl1'
     → 失败 → getContext('2d') 成功 → kind='canvas2d'
     → 失败 → 纯 CSS 环（.vc-core-css，conic-gradient + @keyframes）→ kind='css'
     → 全部失败/`quality:'off'` → kind='none'（只留状态点，不报错）
```

- `webglcontextlost` 事件 → 立刻 `preventDefault()`、销毁程序、**降一级重来**（webgl2→webgl1→2d→css），并把这次降级记在 `frameStats()` 里、控制台 `[voice-companion] core:downgrade`。
- 前端 fake DOM 没有 `getContext`（`test/avatar-harness.mjs:101-141` 只实现 createElement/createElementNS），所以 harness 里必然走 `css`/`none`，**不会因为 3D 挂掉**。这条是硬性验收：`createAvatar` 在无 canvas 环境下必须照常返回。
- 画质：`quality:'auto'` 时测最近 30 帧平均耗时，>22ms 就重建 LITE 程序（24 步、`renderScale 0.65`），仍 >28ms 就降到 `canvas2d`；`high` 固定 40 步、scale 1.0。
- 省电：`document.hidden` 停 rAF；`collapsed` 或 `state==='idle'` 限 30fps（`motion.idleFps`）；`reducedMotion` 只画静态帧。

**降级路径完整性**：WebGL2 → WebGL1 → 2D canvas → 纯 CSS → 无（只剩状态点）。每一级都实现 `setState/setLevel/setTheme/dispose`，上层无感。

## 3. 主题 token schema

### 3.1 怎么把 `STYLE_TEXT` 变量化（可机械执行的改造规则）

1. **保留一份结构样式表**：`STYLE_TEXT`（`avatar.js:52-182`）继续存在，但**所有视觉值改成 `var(--vc-…, <原值>)`**。带 fallback 的好处：主题还没加载/加载失败时，视觉与 v0.3 完全一致，P0 阶段可以做到「零视觉 diff」。
2. **新增一份主题样式表**：`<style data-vc-theme-style>`（每 document 一个，和 `ensureStyles` 同构，`avatar.js:205-215`），内容只有 `[data-vc-avatar]{--vc-…: …}` 与 `[data-vc-avatar] .vc-<part>{…}`（专家 CSS 层）。**改主题 = 改这个元素的 textContent**，不重建结构样式表，也不碰 `client.js`。
3. **命名规则**：token 用点分组 `group.role`，转 CSS 变量时 `--vc-` + 点/驼峰转 kebab：`board.bgFrom → --vc-board-bg-from`、`core.palette.idle.rim → --vc-core-palette-idle-rim`。转换函数 `cssVarName(key)` 是纯函数，必须单测。
4. **每个 token 有类型**：`color | length | number | duration | easing | shadow | gradient | enum | font | css`。类型决定校验与序列化（第 4 章双层校验共用同一份 schema）。
5. **不引 `!important`、不引 `@media`**：响应式（窄屏 340→300）由结构样式表自己处理，主题不参与，避免用户主题把布局改崩。

### 3.3 允许用户直写 CSS 吗？——允许，但只允许「声明块」，且必须过消毒器

裁决：**不允许任意选择器/任意属性**。原因：主题会被模型生成，模型输出必须当作不可信输入；一旦允许 `@import`/`url()`/`position:fixed`，一个"主题"就能把看板变成全屏遮罩或外链请求。

形态：

```json
{ "v": 1, "name": "赛博朋克红黑",
  "tokens": { "board.bgFrom": "#12040a", "accent.base": "#ff2a4d" },
  "css": { "panel": "box-shadow: 0 0 28px rgba(255,42,77,.45); border-color: rgba(255,42,77,.6)",
           "bubble": "letter-spacing: .02em" } }
```

`css` 的键是**固定枚举**的部件名：`root|panel|head|dot|label|chip|mode|gear|min|start|end|stage|bubble|partial|receipt|sheet|field|ripple|thinkDots|core`（20 个）。值是一串声明，消毒规则：

| 规则 | 具体 | 违背后 |
| --- | --- | --- |
| 拒绝任何 `@`（`@import`/`@media`/`@font-face`） | 出现即整段丢弃 | drop |
| 拒绝 `{` `}` `<` `>` `<!--` | 防选择器注入与 HTML 上下文逃逸 | drop |
| 拒绝 `url(`、`expression(`、`javascript:`、`behavior`、`-moz-binding`、`\` 转义、`/*` | 外链/脚本/IE 老洞 | drop |
| 属性白名单（约 30 个） | `color\|background*\|border*\|border-radius\|box-shadow\|text-shadow\|font-*\|letter-spacing\|line-height\|opacity\|filter\|backdrop-filter\|mix-blend-mode\|transform\|transform-origin\|animation\|transition\|padding*\|gap\|outline*` | 其余 drop |
| 属性黑名单（覆盖白名单） | `position\|inset\|top\|right\|bottom\|left\|z-index\|display\|pointer-events\|content\|visibility\|float\|flex*\|grid*\|width\|height\|margin` | drop，防止把看板挪出屏幕或挡住整页 |
| 值里只允许 `var(--vc-[a-z0-9-]+)` 形式的 `var()` | 正则整体匹配 | 不匹配 drop |
| 长度 | 每部件 ≤ 300 字符、≤ 12 条声明；整份 `css` ≤ 3000 字符 | 截断/拒绝 |
| 序列化 | **永远由我们重新拼字符串**（`prop + ':' + value + ';'`），绝不把用户原文直传 `textContent` | 结构性保证 |

消毒器是纯函数 `sanitizeTheme(input)`（`src/client/theme.js`），返回 `{ theme, dropped: string[] }`；客户端与宿主共用同一份实现（第 4 章）。

### 4.2 300 tokens 装不下怎么办：给通道加 per-call 覆盖，不新建通道

- 现状：`host/persona.js:246-255` 写死 `temperature:0.6, max_tokens:300`；两条测试钉死这两个值（`test/host-companion.test.mjs:311`、`test/persona.test.mjs:102`）。
- 改法：`createBrain` 内部把「一次补全」抽成 `request(messages, { maxTokens = 300, temperature = 0.6, timeoutMs = 30_000 })`；`decide()` 不传参数 → 默认值与测试断言**完全不变**。主题设计器调用 `request(messages, { maxTokens: 900, temperature: 0.35, timeoutMs: 20_000 })`。
- 为什么 900 够：模型只输出**增量 patch**（`set` 里 6-15 个键 + 至多 2 个部件 CSS + name + message），实测这类 JSON 通常 180-320 tokens `[推]`，900 是 3 倍余量。不用 1200+ 是因为越长的输出越容易夹解释文字，容错解析压力大。
- 为什么不做流式：`host/http.js` 只有整包 `sendJson`，`/events` 是游标轮询、没有 SSE；流式要新写一套响应路径，收益只是 1-3 秒的首字延迟，不值得。**明确否决**。

### 4.4 双层校验

1. **宿主层**（`host/theme.js`）：`parseThemeReply(text)` → 先剥 ```json 围栏、再取第一个 `{` 到最后一个 `}`（照抄 `host/persona.js:83-116` 的容错策略）→ JSON.parse → `sanitizeTheme(reply.set/reply.css)`。宿主只接受 schema 内的键；非法键计入 `dropped`，不报错。若 `set`/`css` 全空且没有 `name` → 502 `model-empty-patch`（**不能**把空 patch 当成功返回，否则客户端会"应用了一个什么都没变的主题"）。
2. **客户端层**（`src/client/theme.js` 同一份 `sanitizeTheme`）：应用前再跑一次，且额外校验**合并后**的整份主题（防止分片 patch 组合出非法值）。返回 `{theme, dropped}`；`dropped.length > 0` 时在字幕里提示「已忽略 N 个不支持的样式项」。

同一份 schema、同一个函数，宿主与客户端各跑一次 = 双保险，且不可能漂移（`src/client/theme.js` 是标准 ESM，宿主可以 `import`；先例是 `src/client/voice-profile.js`，它同时被 `src/client/index.js:9` 和 node 测试加载）。

### 4.5 失败回退（按序）

1. 路由超时/502/503 → 字幕「模型没接上，先按本地词表改」→ 用 `LOCAL_STYLE_LEXICON`（约 12 组关键词→token 预设：赛博朋克/霓虹/极简/玻璃/暗黑/红黑/暖色/冷色/大字号/小圆角/无边框/高对比）本地生成 patch，**不落库**，只做预览。
2. 模型返回不可解析 → 同上。
3. 模型 patch 被全部丢弃 → 保留当前主题 + 错误字幕，不弹模态。
4. 用户中途取消（Esc/关抽屉）→ `AbortController.abort()`，丢弃响应。

### 4.6 并发 / 超时 / 防滥用

- 客户端单飞：`designing` 标志 + 上一个 `AbortController`；超时 20s（`requestJson` 已支持第三参数，`src/client/index.js:54-83`）。
- 宿主：`inFlight` 上限 2，超了直接 429；令牌桶 8 次/分钟 + 60 次/小时（进程内，插件重启归零，够用）。
- 输入上限：utterance ≤ 200 字（按 code point 计）、base ≤ 8KB（序列化后字节）、`keep` ≤ 16 项。
- **为什么这不算「任意写入口」**：宿主不落盘（已核实无 writeFile/mkdir）、不写 localStorage（那是浏览器侧，且必须过客户端校验）、不把用户 URL 拿去 fetch、响应里不回显上游原文、没有新增任何"读文件/执行命令"的能力面。它唯一的副作用是**花一次模型调用**，所以防护手段是限额而不是鉴权。
- 残留风险如实写：同源页面里的任何脚本（含被注入的第三方）都能调这条路由花你的 key。这是现有 9 条路由的既有问题（`host/http.js:106-121` 缺 Origin 放行），v0.4 **不引入新洞，但也不修它**——修它要动 `jsonRoute` 的签名，属于独立安全任务（见第 9 章）。

## 5. 主题持久化

### 5.1 localStorage 结构

现有键全部保留不动（`src/client/index.js:13-16`、`avatar.js:588-589`、`hotkey.js:10`）。新增 3 个键，统一前缀：

| 键 | 值 | 上限 |
| --- | --- | --- |
| `dsh.voice-companion.theme.lib` | `{"v":1,"rev":<int>,"activeId":"default","items":[…]}` | 200KB（序列化后） |
| `dsh.voice-companion.theme.active` | 主题 id 字符串（冗余存一份，lib 损坏时可单独恢复） | 64B |
| `dsh.voice-companion.theme.corrupt` | 最近一次解析失败的原始字符串（只留 1 份，用于用户导出报障） | 32KB |

`items[]` 单项：

```json
{ "id":"t_1731a2b3", "name":"赛博红黑", "base":"default",
  "tokens":{…}, "css":{…},
  "createdAt":1731…, "updatedAt":1731…, "source":"ai|manual|import" }
```

`default` 是**内置主题**（不在 items 里，由 `DEFAULT_THEME` 常量提供），所以「删到只剩 0 个自定义主题」永远合法。

### 5.2 CRUD

| 操作 | 行为 | 边界 |
| --- | --- | --- |
| 新建（从当前/AI patch） | `id = 't_' + Date.now().toString(36) + rand4`；同名自动加 `·2` | 上限 24 个；超了拒绝并提示删除 |
| 重命名 | 只改 name，≤ 16 字 | 空名回落原名 |
| 覆盖更新 | `updatedAt` 变，`rev++` | 应用中的主题被覆盖 → 立即重新 apply |
| 删除 | 从 items 移除；若删的是 active → 自动切 `default` 并 apply | 不允许删 `default` |
| 切换 | 写 `theme.active` + `lib.activeId` + 立即 apply | 目标不存在 → 回落 `default` |

### 5.3 导出 / 导入（纯前端）

- 导出：`JSON.stringify({v:1,name,tokens,css,exportedAt}, null, 2)` → `new Blob([...], {type:'application/json'})` → `URL.createObjectURL` → 隐藏 `<a download="vc-theme-<name>.json">` → click → `revokeObjectURL`（延时 1s）。单个主题导出；「导出全部」给 `{v:1, items:[…]}`。
- 导入：`<input type="file" accept="application/json">`（复用 `avatar.js` 已有的 `.vc-file` 模式，`:294-300`），`FileReader.readAsText`（已有 `readImageFile` 的同类实现，`:636-668`）→ 8KB 上限 → `JSON.parse` → `sanitizeTheme` → 分配新 id（避免覆盖）→ 入 items。
- 失败提示：非 JSON / 版本不认识 / 全部 token 非法 → 字幕提示，不写入。

### 5.4 旧键迁移

- `.character` 已是 `whale|chibi|custom` 的用户：**保留其选择**（尊重既有偏好），但把默认值改成 `core`（`characters.js:311-341` 的 `DEFAULT_CHARACTER = CHARACTERS[0].id` 会随数组顺序变，所以显式加 `core` 到数组首位或改常量赋值）。
- `.face`（自定义图片）保留：`resolveCharacter` 的 custom 分支不动（`characters.js:396-411`）。
- 旧版没有主题概念：首次启动写 `theme.lib = {v:1,rev:0,activeId:'default',items:[]}`，不迁移任何视觉值（`DEFAULT_THEME` 就是 v0.3 的视觉）。
- 迁移标记：`lib.v === 1` 即视为已迁移；未来 v2 在 `migrate(raw)` 里按版本链处理。

### 5.5 损坏恢复

1. `JSON.parse` 失败 / `items` 不是数组 / 单项缺 id → 把原文存进 `theme.corrupt`（覆盖旧的）→ 用 `DEFAULT_THEME` 重建空库 → 字幕提示「主题数据损坏，已重置（可在设置里导出损坏数据）」。
2. 单项 token 非法 → 只丢该主题的非法 token（`sanitizeTheme`），不整库重置。
3. `QuotaExceededError` → 依次淘汰最旧的、非 active 的主题，重试一次；仍失败 → 提示「主题库已满，请导出后删除」并**不写入**（当前会话仍生效，只是不持久）。
4. 容量上限按 200KB 自管（远低于浏览器 5MB 同源配额），并预留 `.face` 的 800KB（`avatar.js:56` 的 `FACE_MAX_BYTES`）。

| 弱机掉帧 | 集显 + 高分屏，SDF 40 步 | `auto` 画质：30 帧滑窗 >22ms 降 LITE（24 步/0.65 scale），>28ms 降 canvas2d；idle 30fps；`document.hidden` 停帧 | 极端机器仍可能 20fps `[推]` |

| 消毒漏洞 | 模型/用户输出恶意 CSS | 只允许声明块 + 属性白/黑名单 + 重新序列化 + 永不用 `innerHTML`；`url(`/`@`/`{` 一律拒 | 新属性绕过需靠 allowlist 默认拒绝（新增属性必须显式加白名单） |
| 无鉴权路由 | 同源任意脚本调 `/theme/design` | 令牌桶 8/min + 60/h、`inFlight≤2`、输入长度上限；不落盘、不回显上游 | **会消耗 key 额度**；未修 Origin 放行（既有问题） |
| localStorage 配额 | 24 个主题 × 8KB + 800KB 图片 | 自管 200KB 上限；`QuotaExceededError` 淘汰最旧非 active；损坏留 1 份备份 | 满库时主题不持久（当前会话仍生效） |
| 3D 兼容 | WebGL 被禁用/黑名单/上下文丢失 | 四级降级 + `webglcontextlost` 自动降一级 | `kind:'none'` 时只剩状态点（可接受） |
| 样式串台 | 主题 `<style>` 是 document 级 | 只作用于 `[data-vc-avatar]` 子树；单实例使用 | 多实例共享主题（不承诺支持） |
| z-index 冲突 | DSH 有其他高层浮层 | 沿用 2147483000（v0.3 已在用，未报冲突）；`board.z` 可调 | 与页面模态的层级关系未逐一核对 `[推]` |
| 品牌观感 | 全息核"像不像贾维斯" | 五态色板 + 扫描线 + 菲涅尔；主题可整体换色 | 主观，需用户看图拍板 |

### 9.2 需要用户拍板（4 个）

1. **是否保留"专家 CSS"层**（允许用户/模型写声明块）。建议保留，因为"完全可定制到每个角落"靠 87 个 token 到不了（比如 `letter-spacing`、`mix-blend-mode`、单部件动画）。代价是多一个消毒面。
2. **旧形象（鲸鱼/小肥鱼/自定义图片）留不留**。建议留在设置里，默认新装是 `core`，老用户保留自己的选择。若要求"彻底只留 3D"，则删 `characters.js:113-310` 的两套 SVG 构造器与 `:311-341` 的 cast 条目（-330 行）与 `FACE_KEY` 链路（-200 行），并连带删 8 条 avatar 断言。
3. **AI 改主题是"先预览再应用"还是"直接应用"**。建议先预览（抽屉里给「应用 / 存为主题」两个按钮，Esc 丢弃），避免一句话把看板改花。
4. **是否接受 +21~24% 的 `client.js` 体积**与弱机降级到 2D 的概率。若不可接受，替代方案是把 3D 做成默认关闭的实验开关（`core.quality:'off'` 默认），体积仍在但视觉退化为 CSS 环。
